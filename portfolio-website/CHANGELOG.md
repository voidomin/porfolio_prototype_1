- [x] Wired up Lenis smooth-scroll (`@studio-freight/lenis` was an installed-but-unused dependency). Read Lenis's actual source first — its default config animates the real document scroll position, so nothing else needed to change — but found and fixed a real regression via Playwright testing: Lenis's own autoResize doesn't reliably catch content-driven height growth (a known Lenis limitation), so the Projects section's dynamically-growing pinned-scroll container could leave Lenis's cached scroll limit stale, silently capping how far the page could scroll with no self-correction. Fixed by checking `scrollHeight` every raf tick and calling `lenis.resize()` on change. Also added `data-lenis-prevent` to every nested-scroll container site-wide (command palette, photography lightbox/filmstrip, project sub-tabs, admin panels) since Lenis intercepts wheel events globally and would otherwise silently break scrolling inside them.

- [x] Depth-parallax on existing section decorations (About's trees, Skills/Publications/Photography's ambient glow layers) — checked first that this wouldn't duplicate the already-global `FloatingLeaves` effect, then gave previously-static decorative layers real scroll-linked movement using the same `useScroll`/`useTransform` technique proven in `SectionDivider.tsx`.
- [x] Fixed Lenis lag on trackpad two-finger scroll — a trackpad gesture fires as `wheel` events (not touch), so it's governed by Lenis's `smoothWheel` easing; at the default `lerp` (0.1) that's ~500ms to converge, fine for discrete mouse clicks but felt like lag on already-smooth continuous trackpad input. Tuned to `lerp: 0.3` (~165ms).

- [x] Phase 1 cross-browser/mobile/accessibility hardening pass — ran four parallel audits (mobile/touch, cross-browser, hydration/edge-cases, accessibility) against the real source, then verified every finding by reading the actual code before fixing anything, and closed it out with real Playwright testing (mobile/desktop screenshots, `prefers-reduced-motion` emulation, coarse-pointer emulation, keyboard-only navigation, a simulated WebGL failure) rather than trusting `tsc`/`eslint`/`build` alone. Notable fixes:
  - Two real, previously-undetected **React hydration mismatches** under a genuine `prefers-reduced-motion` preference: `BirdFlock.tsx` returned `null` client-side but rendered a real (empty) wrapper `<div>` server-side, which cascaded into a "missing `<canvas>`" error on `InteractiveTrail` rendered after it; and `PerspectiveTilt.tsx` (wrapping the entire hero) had the same class of bug. Root cause: framer-motion's `useReducedMotion()` reads the real browser preference synchronously on the client's very first render, while the server always assumes `false` — any render output branching directly on it can diverge. Fixed with a new `useSafeReducedMotion()` hook (`src/hooks/useSafeReducedMotion.ts`) that always matches the server on first paint and updates after hydration completes; applied everywhere the value affects rendered structure/style, including four newly-added scroll-parallax gates (see below).
  - A WebGL context-creation failure (old GPU, disabled flag, some in-app browsers) used to blank the entire hero — `SectionErrorBoundary` only wrapped the whole `HeroSection`, so `HeroScene`'s crash took the headline/CTAs down with it. Now isolated to just the 3D scene.
  - `LoadingScreen.tsx`'s unguarded `sessionStorage` calls, combined with zero root-level error boundaries anywhere in the app, meant a storage-blocked browser context (some private-browsing modes, storage-locking policies, sandboxed embeds) could fail to render the entire site. Guarded the calls and added `src/app/error.tsx` + `src/app/global-error.tsx` as a real safety net.
  - `HeroSection.tsx`'s three anchor links weren't routed through the app's own Lenis-aware `scrollTo()` helper, so native `scroll-behavior: smooth` and Lenis's rAF loop fought each other on click.
  - New `useIsDesktopPointer()` hook (`matchMedia('(min-width) and (pointer: fine)')`) replaces raw `innerWidth` checks in `HeroSection.tsx`/`ProjectsSection.tsx`, so touch tablets/landscape phones no longer get desktop-only interactions (a continuous GPU-costly camera loop; a pinned scroll-jack with hover-only controls that can never fire on touch) they can't use — `ProjectsSection.tsx` also now falls back to its calmer mobile grid under reduced motion regardless of screen width.
  - Fixed the classic "stuck hover" bug on touch (`ProjectCard`, `Magnetic`, `PerspectiveTilt` all now reset on `touchend`/`touchcancel`, since touch synthesizes one `mousemove` on tap but never fires `mouseleave`).
  - New `useFocusTrap()` hook applied to all three `role="dialog"` overlays (Command Palette, both photography lightboxes) — none had a real focus trap or returned focus to the trigger on close before; also fixed a bug where the trap never actually engaged on the two lightboxes because focus was never moved into the dialog on open.
  - Command Palette was completely unreachable on any phone (<768px, `hidden md:flex`); now reachable everywhere.
  - Contact form: `role="alert"` on the status message (previously silent to screen readers), plus a JSON-parse guard so a non-JSON upstream error response can't leak a raw `SyntaxError` to the user.
  - Broken hotlinked gallery images (`gallery.json` mixes local files with live Unsplash URLs) now show a neutral "Image unavailable" placeholder instead of the browser's default broken-image icon, across all four render sites.
  - Print stylesheet now actually hides the fixed decorative layers (nature background, birds, leaves, cursor trail, HUD, chapter intros, FAB) instead of letting them repeat on every printed page.
  - Contrast bumps on several under-4.5:1 text colors (Footer credits, Contact header, Command Palette empty state), safe-area-inset padding on the FAB and Command Palette hint for notched devices, and a themed Firefox scrollbar fallback.
  - Deferred (flagged, not fixed): sub-44px touch targets on the mobile sound toggle and HUD checkpoints (layout risk without live visual re-verification), the `100vh`/`dvh` mobile viewport bug in `ProjectsSection.tsx`'s JS-computed pin height, and alt-text quality on project/blog images (a content decision, not a code defect) — added to `ROADMAP.md`.
