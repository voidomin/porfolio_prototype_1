Cause: `globals.css` had `html { scroll-behavior: smooth }`, and Lenis writes `scrollTop` directly on that element every animation frame (~60/sec); each write restarted the browser's own native smooth-scroll animation before the previous one could progress, so sustained high-frequency input left the page barely moving even though Lenis's JS-side math was correct. Fixed by setting `scroll-behavior: auto`; verified safe since the only other native-scroll fallback in the codebase (`scrollTo()`'s fallback in `src/lib/lenis.ts`) already passes `behavior:"smooth"` explicitly as a JS API option, which overrides this CSS property regardless of its value.
